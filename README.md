# LagScope

[![CI](https://github.com/Cyberwaifuu/lagscope/actions/workflows/ci.yml/badge.svg)](https://github.com/Cyberwaifuu/lagscope/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

LagScope estimates how fast and how strongly sentiment moves from government channels and bloggers to the mass audience. It takes three daily sentiment series and fits the lagged regression

```
s_mass(t) = α + β1 · s_gov(t − k1) + β2 · s_blog(t − k2) + ε(t)
```

where `k1` and `k2` are delays in days chosen by AIC, BIC or HQIC, and `β1`, `β2` are the strengths of influence.

The tool comes from a master's dissertation on Two-Step Flow in Kazakhstan's bilingual (RU/KZ) Telegram space, but any daily sentiment series in the range −1…1 can be used.

## What it does

- Reads a comma-separated UTF-8 CSV and checks it: four columns, consecutive dates, no empty cells, values in [−1, 1], at least 60 rows, no constant series. Every broken rule is reported as a plain sentence.
- Searches every lag pair on one common sample and keeps the pair with the lowest information criterion.
- Estimates the regression by OLS with classical or Newey–West (HAC) standard errors.
- Runs optional diagnostics: ADF (stationarity), Granger (precedence), Ljung–Box (residual autocorrelation).
- Shows the coefficient table and a chart of the three series; exports them as CSV and PNG.

It does **not** score sentiment from raw text, collect posts from social media, or claim causality.

## Input format

| column | type | meaning |
|---|---|---|
| `date` | `YYYY-MM-DD` | one row per day, no gaps |
| `s_gov` | float in [−1, 1] | mean daily sentiment of government channels |
| `s_blog` | float in [−1, 1] | mean daily sentiment of bloggers |
| `s_mass` | float in [−1, 1] | mean daily sentiment of the mass audience |

Any other column is rejected, so message texts cannot enter the tool by accident.

## Installation

Python 3.12, 3.13 or 3.14.

```bash
git clone https://github.com/Cyberwaifuu/lagscope.git
cd lagscope
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
```

## Usage

Web interface:

```bash
streamlit run app.py
```

Switch on "Use the synthetic example" to try it without your own data.

Python:

```python
from lagscope import ModelSpec, load_series, run

frame = load_series("data/synthetic_274.csv")
result = run(frame, ModelSpec(criterion="bic", cov_type="HAC"))
print(result.lags)
print(result.coefficients)
```

## Synthetic data

`data/synthetic_274.csv` covers 2025-12-01 … 2026-08-31 (274 days). It is generated by `scripts/make_synthetic.py` (seed 42) with a known effect: `k1 = 3, β1 = 0.25` and `k2 = 1, β2 = 0.45`. The tests check that LagScope finds these values. The real dissertation corpus is not part of this repository.

## Development

```bash
pip install -r requirements-dev.txt
ruff check .
ruff format --check .
pytest --cov
python scripts/make_synthetic.py --check
```

Every push and pull request to `main` runs the CI workflow: lint, tests on Ubuntu and Windows with Python 3.12, 3.13 and 3.14 (coverage must stay at or above 90%), and a package build. Pushing a tag such as `v0.1.0` runs the release workflow, which attaches the built package to a GitHub release.

## Project structure

```
lagscope/        core package (no Streamlit import)
  io.py          reading and validating the CSV
  spec.py        ModelSpec: all estimation settings
  core.py        lag search, OLS fit, diagnostics
  report.py      coefficient table, chart, CSV/PNG export
app.py           Streamlit interface
reference/       independent NumPy implementation used by the parity test
scripts/         synthetic data generator
data/            synthetic fixture only
tests/           pytest suite
.github/         CI and release workflows, issue and PR templates
```
